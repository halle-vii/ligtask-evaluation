How to configure API keys?

Each person running the system must configure their own key, or an authorized shared project key. The app reads keys when it starts.

macOS · zsh terminal

  1. In the terminal running the system, press Control+C to stop it. Keep the database running.
  2. Paste these commands, then paste your OpenRouter key at the prompt and press Enter. Your key stays hidden. 
    read -s "OPENROUTER_API_KEY?Paste your OpenRouter key, then press Enter: "
export OPENROUTER_API_KEY
echo
  3. Confirm the key is set without displaying it: 
    [[ -n "$OPENROUTER_API_KEY" ]] && echo "Key configured" || echo "Key not set"
  4. From the project folder, start the system again in that same terminal: 
    /Library/Java/JavaVirtualMachines/jdk-22.jdk/Contents/Home/bin/java -jar target/ligtask-evaluation-0.1.0.jar

    This command uses the JDK 22 installation on this Mac. On another computer, use its installed JDK 21–25.

  5. Wait for Started Application, refresh this page, and check that your models show API key configured.
Windows · PowerShell

Stop the system with Control+C, then set the key privately:

$env:OPENROUTER_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'OpenRouter key' -AsSecureString)).Password

From the project folder, restart in the same PowerShell window with JAVA_HOME set to your JDK:

& "$env:JAVA_HOME\bin\java.exe" -jar target/ligtask-evaluation-0.1.0.jar

Wait for startup to finish, then refresh this page.

Hugging Face models · optional

For Llama, Qwen and Dolphin, configure HUGGINGFACE_API_KEY before restarting. In macOS zsh:

read -s "HUGGINGFACE_API_KEY?Paste your Hugging Face key, then press Enter: "
export HUGGINGFACE_API_KEY
echo

In PowerShell, use the Windows command above with HUGGINGFACE_API_KEY instead of OPENROUTER_API_KEY.

Delete API keys when you are done

Important: delete your API keys when you finish your runs to prevent unauthorized use and unexpected charges. Remove them from your terminal and delete or revoke keys you no longer need in your provider account.

  1. Wait for your runs to finish, then press Control+C in the terminal running the system to stop it. Removing a terminal variable does not remove the key from an app that is already running.
  2. In that same terminal, remove both keys:

    macOS · zsh

    unset OPENROUTER_API_KEY HUGGINGFACE_API_KEY

    Windows · PowerShell

    Remove-Item Env:OPENROUTER_API_KEY, Env:HUGGINGFACE_API_KEY -ErrorAction SilentlyContinue
  3. Sign in to OpenRouter or Hugging Face, open your API key or access token settings, and delete or revoke the key you used when it is no longer needed. Removing a key from your terminal does not revoke it with the provider. For a shared project key, coordinate with the owner before revoking it.
  4. If you saved a key in a shell profile, environment settings, or a configuration file, remove it there too. Restart the system without the keys and refresh this page to check that the models show API key missing.

Keep the key private. Do not put it in source files, Git, screenshots, or chat. These commands keep it out of terminal history. A new terminal session needs the key configured again.

A configured key does not guarantee credits, provider access, or model availability. For the first test, select one model, keep One prompt (test), and acknowledge provider charges before starting.

Retry failed and unfinished requests?

      

      
Retries use the original input and model settings. Each request may incur new provider charges. Successful responses are reused without another model call.

      
      
      

      

    
    
      
Delete saved run?

      
Run  and its unshared responses will be permanently deleted. Responses referenced by another saved run are retained. Dataset prompts are retained.

      
Deleting unshared responses also clears their reuse history. Evaluating those requests again may incur provider charges.
